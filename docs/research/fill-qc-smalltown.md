## Coverage notes (read before using this file)

**Tooling problem, disclosed up front:** the standard web-search tool (`WebSearch`) had already used its entire per-session budget (200/200) before this task started (shared across other work in this session), so it returned zero results for every query issued. I fell back to the self-hosted Firecrawl proxy configured on this machine (`firecrawl` CLI), but its `search` command 404s (the self-hosted instance has no search provider configured), and scraping Google, Bing, DuckDuckGo (both `html.` and `lite.` endpoints), Startpage, and search.marginalia.nu directly all failed — consent walls, JS/anomaly challenges, bot-verification pages, or (marginalia) English-only indexing. `locator.wizards.com` (Wizards of the Coast Magic store locator) renders its search client-side via JS that the scraper cannot trigger — it always returns "No results found," even for Montreal, which is known to have WPN stores, so that source could not be used at all. `cardshophub.com` is US-only (confirmed on its homepage: "the largest U.S. directory... 50 states"), no Canada coverage. Facebook (desktop and mobile) is fully login-walled to the scraper — no business-page content could be read, so any lead whose only source was a bare Facebook link could not be verified and was excluded.

**What I used instead:** PagesJaunes.ca (Yellow Pages Canada), which renders server-side and worked reliably. For each target town I ran several category searches — "collectionneur" (maps to the curated "Articles de collectionneurs" category), "boutique de jeux," "jeux et jouets," "bandes dessinées," "pokemon," and "carte à jouer" — and inspected every result. I also re-checked `cartesdehockey.ca`'s hand-maintained "Magasins et boutiques" shop list in full; it is dated (last updated June 2021) and every shop on it was already in the existing roster — no new towns.
